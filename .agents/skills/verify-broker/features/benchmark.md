# Frozen replicated broker benchmark

Run `python -m unittest discover -s coursework -p test_benchmark.py -v` then `python coursework/benchmark.py smoke`. The smoke launches three actual NATS processes plus the adapter, publishes two deterministic payloads and requires matching stream sequence, full payload and consumer ACK before cleanup. Its timings are not performance evidence.

`python coursework/benchmark.py benchmark` requires isolated Linux. Version 1 covers 64/1024/16384-byte UTF-8 payloads, producers 1/4/16 and consumers 1/4/16 using eight one-axis cells including the matched one-producer/one-consumer baseline. Five repeats reverse order. Every cell owns fresh three-replica stores, one stream/channel and 64 unique messages. Fixed-rate sweeps offer 10/100/500 messages per second for ten seconds with at most 64 outstanding end-to-end actions. Declines remain recorded. The highest zero-loss rate with dispatch-p99 <100ms and delivery+ACK-p99 <5s receives 120s stability. The unchanged stream retains acknowledged messages under its actual 32MiB cap; a stability run that fills that cap must report storage-bound rejection rather than imply unlimited capacity. Separate 64-message backlog/drain and leader-loss cells preserve stream state before/after. Fault cells retain publish uncertainty; there are no invisible retries.

The driver timestamps intended offer, dispatch, publish acknowledgment and first verified delivery ACK. It checks exact payload bytes and sequence and records duplicate/redelivery attempts, accepted publish ledger and uncertain attempt IDs. Only the first ACK per unique index counts as useful bytes. Raw receipts retain all errors and samples plus /jsz stream/replica/backlog state and tracked server/adapter/generator Linux CPU/RSS samples. JSON workload/environment/source/dirty state lives in `.local/benchmark-*/summary.json`; per-trial evidence is `.local/evidence/*/benchmark/`. Secrets remain in ignored local configs and are excluded from workflow artifacts.

`profile` captures separate native five-second NATS pprof through preexisting loopback-only endpoints plus generator cProfile. Adapter CPU is not profiled; no adapter cause-dependent optimization is justified from server profiles alone. Profiles are not included in performance comparisons. Every process and consumer thread is owned, bounded and checked on cleanup; evidence survives. The read-only manual Ubuntu `Broker benchmark` workflow builds and drives this same path. No measured throughput result is yet published.
